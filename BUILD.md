# Building Math World

The app is a standard Expo prebuild + Gradle project. `android/` is generated
and **gitignored** — regenerate it rather than editing it by hand.

## Prerequisites

- Node 20+
- JDK 17
- Android SDK with platform 36 and build-tools 36 (`ANDROID_HOME` set)

## Debug-signed APK (sideload / testing)

```bash
npm install
npx expo prebuild --platform android --clean
cd android
./gradlew assembleRelease          # Windows: .\gradlew.bat assembleRelease
```

Output: `android/app/build/outputs/apk/release/app-release.apk`

Install it with:

```bash
adb install -r android/app/build/outputs/apk/release/app-release.apk
```

> **This APK is signed with Expo's bundled debug keystore.** It installs and runs
> fine, but it is not suitable for the Play Store or for distribution you intend
> to update later — a debug-signed build cannot be upgraded to a
> differently-signed one without uninstalling.

## Release-signed APK / AAB (distribution)

1. Generate a keystore **once** and keep it somewhere safe and backed up. If you
   lose it you cannot ship an update to the same app listing.

   ```bash
   keytool -genkeypair -v \
     -keystore mathworld-release.keystore \
     -alias mathworld \
     -keyalg RSA -keysize 2048 -validity 10000
   ```

2. Put the credentials in `~/.gradle/gradle.properties` (outside the repo, so
   they are never committed):

   ```properties
   MATHWORLD_UPLOAD_STORE_FILE=/absolute/path/to/mathworld-release.keystore
   MATHWORLD_UPLOAD_STORE_PASSWORD=…
   MATHWORLD_UPLOAD_KEY_ALIAS=mathworld
   MATHWORLD_UPLOAD_KEY_PASSWORD=…
   ```

3. Because `android/` is regenerated by prebuild, the signing config belongs in
   `app.json` rather than in `build.gradle`. Add an
   [`expo-build-properties`](https://docs.expo.dev/versions/v57.0.0/sdk/build-properties/)
   config plugin entry, or switch to EAS Build (below), which manages the
   keystore for you.

4. Build:

   ```bash
   cd android
   ./gradlew assembleRelease    # APK
   ./gradlew bundleRelease      # AAB, for the Play Store
   ```

## EAS Build (cloud, recommended for distribution)

EAS generates and stores the release keystore, so step 1–3 above are handled for
you:

```bash
npx eas-cli login
npx eas-cli build --platform android --profile preview     # installable APK
npx eas-cli build --platform android --profile production  # AAB for the Play Store
```

This requires an Expo account and network access.

## Verifying a build

Always run the full check before building — a green bundle is not the same as a
green app:

```bash
npm run check     # typecheck + content validation + 687 tests
```

To confirm the JS bundles without launching a device:

```bash
npx expo export --platform android --output-dir .expo-export
```

## Notes

- The app is fully offline and makes no network calls at runtime. The manifest
  does declare legacy `READ_EXTERNAL_STORAGE` / `WRITE_EXTERNAL_STORAGE`, both
  capped at `maxSdkVersion="32"` — these are inherited from the Expo asset
  modules and are inert on Android 13+. No permission is requested at runtime.
- `minSdkVersion` 24, `targetSdkVersion` 36, `compileSdkVersion` 36.
- The universal APK carries all four ABIs (~89 MB). Build a single-architecture
  APK for a much smaller download:

  ```bash
  ./gradlew assembleRelease -PreactNativeArchitectures=arm64-v8a
  ```

  `arm64-v8a` covers essentially every Android phone sold in the last several
  years. For the Play Store, ship the AAB instead and let Google split it.
- First launch runs migrations and seeds the bundled content packs, which takes a
  second or two; the splash screen reports each stage.
- `newArchEnabled: true` — the app runs on the New Architecture (Fabric +
  TurboModules).
